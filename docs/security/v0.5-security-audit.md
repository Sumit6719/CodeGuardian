## 1. Executive Summary

An independent, rigorous security audit was conducted on CodeGuardian v0.5 (`codeguardian@0.5.0`). The system was evaluated against 20 specific attack vectors and 12 security architecture categories.

CodeGuardian v0.5 successfully enforces **OS-level execution isolation**, **fail-closed capability selection**, **network containment**, and **state-machine-governed sandbox lifecycles**.

### Key Findings
- **Zero Silent Fallback**: If `CONTAINER` isolation is required and Docker runtime is unavailable, `IsolationFactory` returns `null` and the orchestrator **fails closed (`BLOCK`)**. It never degrades container isolation requirements to un-isolated host execution.
- **Docker CLI Security**: `ContainerIsolationEnvironment` uses `spawn('docker', args, { shell: false })` directly, avoiding shell interpolation and avoiding recursive invocation of CodeGuardian's governed `execute_command` tool.
- **Symlink & Path Hardening**: `EffectFirewall` resolves canonical targets using `fs.realpathSync`, preventing symlinks created inside allowed directories from bypassing path restrictions or `.env` protection.
- **TOCTOU Revalidation**: `PathGuard.validate()` revalidation is enforced for all tool operations (`WRITE`, `DELETE`, `EXECUTE`) immediately before execution.
- **Evidence Integrity**: All v0.5 sandbox lifecycle events are cryptographically chained in `evidence.jsonl`. Infrastructure files (`evidence.jsonl`, `audit.log`) are excluded from workspace state snapshots and protected against rollback erasure.

## 3. Architecture Review

CodeGuardian v0.5 enforces a strictly governed, unbypassable execution flow:

```text
POLICY → CAPABILITY → ISOLATION_FACTORY → SANDBOX_ENVIRONMENT → EXECUTION → OBSERVATION → VERIFICATION
```

The architecture decouples untrusted LLM proposals from OS execution. All actions pass through 12 security gatekeepers before reaching the sandbox environment. If any stage fails or rejects the proposal, the system defaults to `BLOCK` or `DENY`.

## 4. Isolation Provider Review

| Provider | Isolation Level | Availability Check | Failure Mode |
|----------|-----------------|--------------------|--------------|
| `ContainerIsolationProvider` | `CONTAINER` | Runs `docker info` (3s timeout) | Returns `isAvailable() = false` if daemon unresponsive |
| `ProcessIsolationProvider` | `PROCESS` | Always `true` on host OS | Enforces process group / Job Object bounds |
| `HostFallbackProvider` | `PROCESS` | Always `true` on host OS | Enforces v0.4 `SecureProcessExecutor` bounds |

### Provider Level Comparison Verification
`IsolationFactory` checks:
$$\text{ISOLATION\_LEVEL\_WEIGHTS}[\text{actual}] \ge \text{ISOLATION\_LEVEL\_WEIGHTS}[\text{required}]$$

- `requiredIsolationLevel = CONTAINER`, available = `PROCESS` $\rightarrow$ **`ISOLATION_UNSATISFIABLE` (`BLOCK`)**
- `requiredIsolationLevel = NETWORK`, available = `PROCESS` $\rightarrow$ **`ISOLATION_UNSATISFIABLE` (`BLOCK`)**
- `requiredIsolationLevel = PROCESS`, available = `PROCESS` $\rightarrow$ **Allowed**

Weaker providers can **never** satisfy stronger isolation requirements.

## 5. Docker Security Review

### Command Line Construction
Containers are launched using array arguments passed directly to `spawn('docker', args, { shell: false })`:
- `--rm`: Automatic container removal after execution.
- `--read-only`: Root filesystem mounted read-only.
- `--cap-drop=ALL`: All Linux capabilities dropped.
- `--user node`: Unprivileged non-root execution.
- `--network none`: Network interface revocation when `networkPolicy.mode === 'NONE'`.
- `-v workspace:workspace:ro`: Workspace root mounted read-only.
- `-v allowedPath:allowedPath:rw`: Only explicitly allowed write paths mounted read-write.
- `--memory`, `--cpus`, `--pids-limit`: Bounded resource limits applied.

### Cleanup Guarantee
Container teardown (`docker rm -f <containerId>`) is executed in `finally` blocks in `ContainerIsolationEnvironment.destroy()` and `AgentOrchestrator.run()`, ensuring cleanup on success, error, or timeout.

## 6. Network Security Review

- **Container Mode**: When `networkPolicy.mode === 'NONE'`, `--network none` is passed to Docker. The container has no network interfaces (except loopback), guaranteeing kernel-level network isolation.
- **Host Mode**: Uses `NetworkPolicyValidator` to validate observed host/port targets post-execution against allowlists.
- **Clarity**: Documentation explicitly distinguishes kernel-level container network denial (`--network none`) from host-level heuristic argument parsing.

---

## 7. Process Security Review

- **Unix**: Spawned with `detached: true` in a new process group; killed via `process.kill(-pid, 'SIGKILL')` on timeout or failure.
- **Windows**: Process tree terminated via `taskkill /F /T /PID <pid>`.
- **Environment Sanitization**: `SecureProcessExecutor.getSanitizedEnv()` strips non-whitelisted parent environment variables and sensitive key/value pairs.

---

## 8. State Machine Review

`SecurityStateMachine` enforces valid transitions across 12 lifecycle states:
`PROPOSED` $\rightarrow$ `PARSED` $\rightarrow$ `POLICY_CHECKED` $\rightarrow$ `CAPABILITY_GRANTED` $\rightarrow$ `ISOLATION_PREPARED` $\rightarrow$ `ISOLATION_VERIFIED` $\rightarrow$ `PROCESS_STARTED` $\rightarrow$ `PROCESS_RUNNING` $\rightarrow$ `PROCESS_TERMINATED` $\rightarrow$ `EFFECTS_VERIFIED` $\rightarrow$ `COMPLETED` (or `VIOLATED` $\rightarrow$ `ROLLED_BACK`).

- Out-of-order transitions throw `SecurityStateError` and fail closed.
- All state transitions record `fromState`, `toState`, `timestamp`, and `reason` in an auditable history log.

---

## 9. Capability Review

- `CapabilityGrant` includes `requiredIsolationLevel`, `networkPolicy`, `resourceLimits`, and `filesystemPolicy`.
- `CapabilityManager.generateGrant()` populates fields deterministically based on action operation and risk tier.
- LLM outputs cannot modify or request elevated capability grants.

---

## 10. TOCTOU Review

- Revalidation of target paths (`PathGuard.validate()`) is performed in `AgentOrchestrator` immediately before calling `tool.execute()` for all tool operations (`WRITE`, `DELETE`, `EXECUTE`).
- Target paths are canonicalized (`fs.realpathSync`) before checking workspace boundary containment.

---

## 11. Evidence Ledger Review

- All v0.5 events (`ISOLATION_REQUESTED`, `ISOLATION_CREATED`, `ISOLATION_VERIFIED`, `ISOLATION_FAILED`, `SANDBOX_PROCESS_STARTED`, `SANDBOX_PROCESS_TERMINATED`, `SANDBOX_DESTROYED`, `ISOLATION_VIOLATION`) are appended to `evidence.jsonl`.
- Records are cryptographically linked using SHA-256 hash chains (`previousRecordHash`).
- `EffectObserver` excludes `evidence.jsonl` and `audit.log` from workspace state snapshots, ensuring evidence files are never erased during rollback.
- `serializeObservedEffects()` scrubs secrets matching key/token/password regexes before logging.

## 13. Security Guarantees

CodeGuardian v0.5 technically guarantees:

1. **Fail-Closed Permission & Isolation Model**: Any un-allowlisted command, expired capability, or unsatisfied isolation requirement results in immediate execution `BLOCK`.
2. **Deterministic Risk & Capability Grants**: Security decisions and capability bounds are computed independently of LLM self-assessments.
3. **Container Network Revocation (`--network none`)**: Real Linux network namespace interface revocation when executing inside container sandboxes.
4. **Cryptographic Tamper-Evident Ledger**: Hash-chained audit logging that detects unauthorized modification or deletion of audit records.
5. **Automatic Verified Rollback**: Post-execution filesystem mutations outside allowed capability paths are automatically rolled back and verified via SHA-256 content hashes.

---

## 14. Known Limitations

1. **Host-Mode Process Isolation**: Without Docker container runtime, `ProcessIsolationProvider` relies on OS process group boundaries rather than Linux kernel cgroups/namespaces.
2. **Host-Mode Network Detection**: Host-level process execution uses heuristic network argument parsing rather than kernel eBPF socket filtering.
3. **Excluded Directories**: `node_modules`, `dist`, and `.git` are excluded from `EffectObserver` state hashing for performance.
4. **Fast Write-Delete Ephemeral Mutations**: Files created and deleted within the process execution window without leaving post-execution disk artifacts are not detected by userspace before/after state diffing.
