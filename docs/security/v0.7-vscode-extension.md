# CodeGuardian v0.7 — Functional VS Code Extension Architecture & Security Boundary

**Date**: 2026-08-29  
**Version**: `codeguardian@0.7.0`  
**Architecture Milestone**: Functional Developer-Facing VS Code Extension Integration with Governed Execution.

---

## 1. Executive Summary

CodeGuardian v0.7 introduces a **functional developer-facing VS Code extension**. It exposes CodeGuardian's governed AI security pipeline directly inside VS Code through an interactive Webview panel (`codeguardian.openPanel`). Developers can submit natural-language development requests, review risk evaluations and file diffs, approve or reject sensitive actions (`ASK_USER`), monitor regression test runs, and trigger atomic rollbacks—all while preserving every v0.5/v0.6 security guarantee.

---

## 2. Absolute Security Invariants

1. **Untrusted LLMs**: Model providers remain untrusted proposal generators. Model consensus or disagreement can NEVER grant capabilities or turn `BLOCK` into `ALLOW`.
2. **Zero Alternate Execution Paths**: Webview code and VS Code extension commands (`codeguardian.start`, `codeguardian.audit`, `codeguardian.rollback`) CANNOT execute OS shell commands, spawn child processes, or write directly to project files.
3. **Governed Pipeline Enforcement**: Every action requested via VS Code follows the single governed path:
   ```text
   Webview Panel
        ↓
   WebviewProtocol Validation (Strict Runtime Schema Check)
        ↓
   ExtensionHostBridge
        ↓
   AgentOrchestrator
        ↓
   Deterministic Security Pipeline (RiskEngine & PolicyEngine)
        ↓
   CapabilityManager & IsolationFactory (Process / Container Sandboxes)
        ↓
   EffectObserver & EffectFirewall
        ↓
   RegressionGuard (Post-Apply Test Suite Verification)
        ↓
   EvidenceLedger (Cryptographic SHA-256 Hash Chain)
   ```
4. **Secret Redaction**: API keys (`sk-ant-`, `sk-`, `GEMINI_KEY`) and credentials are automatically scrubbed (`[REDACTED_SECRET]`) from all Webview updates, logs, and error messages.

---

## 3. Webview Protocol & RPC Commands

The extension host communicates with the Webview UI via strongly typed, schema-validated JSON-RPC messages (`validateWebviewMessage`):

- `PING` / `START`: Pipeline initialization
- `SUBMIT_PROPOSAL`: Natural language prompt submission
- `APPROVE` / `REJECT`: Explicit user decision resolution for `ASK_USER` policy prompts
- `ROLLBACK`: Triggers `RollbackManager.rollback()` with hash verification
- `GET_STATE` / `GET_DIFF`: Status and file diff inspection
- `GET_EVIDENCE`: Sanitized tamper-evident audit ledger retrieval
- `SELECT_MODEL`: Switches configured AI model providers (`gemini`, `claude`, `openai`, `ollama`)

---

## 4. Threat Model & Injection Countermeasures

| Threat Vector | Mitigation Strategy |
|---------------|---------------------|
| Webview Command Injection | `validateWebviewMessage()` verifies command names against strict enum whitelist. |
| Path Traversal in Webview RPC | Paths containing `..` or null bytes (`\0`) throw `WebviewProtocolError` immediately. |
| Payload Flooding | Webview message payloads are capped at 1MB. |
| Secret Leakage in UI | `WebviewPanelController.sanitizeSecrets()` scrubs API keys before posting state updates. |
| Un-Governed OS Execution | Extension host contains ZERO `child_process` execution calls; all tasks pass to `AgentOrchestrator`. |

---

## 5. VSIX Packaging

The extension is packaged via `@vscode/vsce`:
```bash
npm run package
```
Strict `.vscodeignore` rules guarantee that secrets (`.env`), tests, documentation, and temporary log files are excluded from the VSIX bundle.
