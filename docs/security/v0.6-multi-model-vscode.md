# CodeGuardian v0.6 — Multi-Model Provider Independence & VS Code Security Boundary

**Date**: 2026-08-29  
**Version**: `codeguardian@0.6.0`  
**Architecture Milestone**: Multi-Model Provider Independence, Consensus Disagreement Detection, VS Code Extension Bridge, and Automated Regression Guard.

---

## 1. Multi-Model Provider Architecture

CodeGuardian v0.6 decouples execution from any single AI vendor. It introduces provider drivers for:

- **Google Gemini** (`GeminiProvider`): Default model `gemini-2.5-flash`
- **Anthropic Claude** (`ClaudeProvider`): Default model `claude-3-5-sonnet`
- **OpenAI** (`OpenAIProvider`): Default model `gpt-4o`
- **Local Ollama** (`OllamaProvider`): Local REST models (`qwen2.5-coder`, `codellama`)

### Trust Model & Unconfigured Fallback
- Model providers are **untrusted proposal generators**.
- Providers implement `isConfigured(): boolean`. Missing API keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) or offline local servers do NOT crash the platform; `ModelProviderRegistry` filters out unconfigured providers gracefully.
- API keys and tokens are scrubbed from logs, errors, and Webview messages via regex filters (`[REDACTED_SECRET]`).

## 2. Multi-Model Disagreement Detection (`ModelDisagreementDetector`)

When multiple models evaluate the same user goal:
- Proposals are compared across operation types, target file paths, parameter diffs, and risk scores.
- Divergent operations on critical assets (`.env`, `.git`) or opposing file operations calculate high disagreement scores ($\ge 0.3$) and escalate risk to `HIGH` / `ASK_USER`.
- **CRITICAL INVARIANT**: Model consensus **NEVER** bypasses deterministic security policies (`CommandPolicy`, `PathGuard`, `CapabilityManager`, `IsolationFactory`, `EffectFirewall`). Model agreement cannot upgrade an unauthorized command to `ALLOW`.

## 3. Automated Regression Guard (`RegressionGuard`)

Post-modification verification executes project regression tests inside v0.5 isolation sandboxes:

```text
WRITE OPERATION → AST SYNTAX VERIFICATION → SANDBOX EXECUTION → EFFECT OBSERVATION → REGRESSION GUARD (npm test / pytest / cargo test inside sandbox) → EVIDENCE LEDGER
```

- **Sandbox Enforcement**: `RegressionGuard` runs test runners inside `IsolationFactory` sandboxes (`requiredIsolationLevel: 'PROCESS'`). It **never** spawns un-isolated commands directly on the host.
- **Automatic Rollback**: If project unit tests fail post-modification (`REGRESSION_DETECTED`), `RollbackManager` restores pre-modification file snapshots and logs the rollback to the cryptographic evidence ledger.
- **Anti-Recursion**: Prevents infinite loops via `CODEGUARDIAN_REGRESSION_ACTIVE` process flags when CodeGuardian tests itself.

## 4. VS Code Extension Foundation (`ExtensionHostBridge` & `WebviewProtocol`)

The VS Code integration connects the Webview UI panel to CodeGuardian core:

```text
Webview UI ──(postMessage)──> WebviewProtocol (Schema Validation) ──> ExtensionHostBridge ──> AgentOrchestrator Pipeline
```

- **Runtime Schema Validation**: `validateWebviewMessage()` inspects incoming JSON-RPC payloads, rejecting unknown commands, malformed fields, path traversal, null bytes, or payloads exceeding 1MB.
- **No Alternate Execution Path**: All user requests submitted via VS Code execute through the full 12-stage `SecurityStateMachine` pipeline.
- **Secret Redaction**: `WebviewPanelController` scrubs API keys and sensitive tokens before sending UI updates.
