# CodeGuardian v0.4 — Effect Firewall & Change Impact Intelligence

## Overview

CodeGuardian v0.4 evolves the platform from a **deterministic command execution security boundary** (v0.3.1) into a **capability-aware Effect Firewall** that:

1. Observes actual filesystem effects produced by process execution
2. Compares observed effects against the granted capability
3. Detects unauthorized mutations (files created/modified/deleted outside allowed paths)
4. Calculates change impact and blast radius
5. Performs **verified, atomic rollback** on capability violations
6. Records all security-relevant events in the tamper-evident cryptographic evidence ledger

---

## Architecture

```text
AI Agent
  ↓
Action Proposal (EXECUTE tool call)
  ↓
CommandParser           → structural parse, operator detection
  ↓
ExecutableResolver      → path resolution, trust classification
  ↓
NpmScriptAnalyzer       → recursive script chain evaluation
  ↓
CommandPolicy           → deterministic allowlist/blocklist
  ↓
CapabilityManager       → generate bounded CapabilityGrant
  ↓
PolicyEngine            → final ALLOW / ASK_USER / BLOCK decision
  ↓
SecureProcessExecutor   → shell:false, env-sanitized execution
  ↓
────────── POST-EXECUTION ──────────
EffectObserver          → workspace state diff (pre vs. post)
  ↓
EffectFirewall          → compare observed effects vs. capability
  ↓
  ├─ PASS → ChangeImpactIntelligence → record EFFECT_DETECTED + CHANGE_IMPACT_CALCULATED
  └─ FAIL → record CAPABILITY_VIOLATION
              ↓
           RollbackManager → atomic rollback of all unauthorized mutations
              ↓
           record EFFECT_ROLLBACK_COMPLETED
```

## New Components (v0.4)

### `src/security/effects/effectTypes.ts`

Defines all shared data contracts:

- `FilesystemEffect` — typed union: `FILE_CREATE | FILE_WRITE | FILE_DELETE | FILE_READ | DIR_CREATE | DIR_DELETE`
- `NetworkEffect` — heuristic network indicators extracted from command line arguments
- `ProcessEffect` — spawned sub-process descriptors
- `ObservedEffects` — container for all three effect categories
- `ExpectedEffects` — capability constraints: `allowedPaths`, `deniedPaths`, `allowNetwork`, `allowedProcesses`
- `serializeObservedEffects()` — secret-scrubbing serialization helper
- Type guard functions: `isFilesystemEffect`, `isNetworkEffect`, `isProcessEffect`

### `src/security/effects/effectObserver.ts`

Captures workspace filesystem state snapshots before and after process execution and detects differences.

**Key behaviors:**

- Recursively hashes all files in the workspace using SHA-256
- **Excludes** system directories: `.git`, `node_modules`, `.codeguardian` (prevents internal snapshot files from appearing as effects)
- **Excludes** CodeGuardian infrastructure files (evidence ledger, audit log) — rolling these back would corrupt the tamper-evident chain
- Resolves all paths to canonical form to prevent symlink-based directory traversal
- Enforces workspace boundary: symlinks pointing outside workspace are silently skipped
- Detects `FILE_CREATE`, `FILE_WRITE`, `FILE_DELETE`, `DIR_CREATE`, `DIR_DELETE` effects

**Configurable exclusions:**
```typescript
new EffectObserver(workspaceRoot, {
  excludedFiles: [config.evidenceLogPath, config.auditLogPath]
})
```

### `src/security/effects/effectFirewall.ts`

Deterministically validates observed effects against the capability grant. Fail-closed.

**Validation rules (in order):**

| Rule | Type | Action |
|------|------|--------|
| `SEC-001-WORKSPACE-BOUNDARY` | Filesystem | Block — target escapes workspace root |
| `SEC-003-CRITICAL-WRITE-PROTECTION` | Filesystem | Block — `.env` or `.git` modification |
| `SEC-002-DENIED-PATH` | Filesystem | Block — target in explicitly denied path list |
| `SEC-004-UNAUTHORIZED-WRITE` | Filesystem | Block — mutation outside `allowedPaths` |
| `NET-001-UNAUTHORIZED-NETWORK` | Network | Block — network activity with `allowNetwork: false` |
| `EXEC-001-UNAUTHORIZED-PROCESS` | Process | Block — spawned process not in `allowedProcesses` |

### `src/security/effects/changeImpact.ts`

Calculates blast radius and severity for legitimate (firewall-passed) executions.

**Scoring:**
- File create: `+15` per file
- File write: `+10` per file (weighted by file size)
- File delete: `+25` per file
- Directory create: `+5`
- Directory delete: `+30`
- Sensitive path bonus: `+20` per sensitive file affected

**Severity classification:**

| Score | Severity |
|-------|----------|
| 0–19 | LOW |
| 20–49 | MEDIUM |
| 50–79 | HIGH |
| 80–100 | CRITICAL |
| >100 | CRITICAL+ |

## New Evidence Ledger Events (v0.4)

All events are appended to the cryptographic hash chain in `evidence.jsonl`:

| Event | When |
|-------|------|
| `EFFECT_DETECTED` | Firewall passed — observed effects recorded |
| `CHANGE_IMPACT_CALCULATED` | Impact score computed post-firewall |
| `CAPABILITY_VIOLATION` | Firewall detected unauthorized effect |
| `EFFECT_ROLLBACK_COMPLETED` | All unauthorized mutations successfully rolled back |
| `ROLLBACK_CRITICAL_FAILURE` | Partial rollback — manual intervention required |

---

## Rollback Behavior

When a `CAPABILITY_VIOLATION` is detected, CodeGuardian performs atomic rollback:

1. For each detected filesystem effect:
   - `FILE_CREATE` → delete the created file (null-snapshot rollback)
   - `FILE_WRITE` → restore from pre-execution snapshot
   - `FILE_DELETE` → restore from pre-execution snapshot
   - `DIR_CREATE` → remove the created directory recursively
   - `DIR_DELETE` → recreate the empty directory
2. Infrastructure files (`evidenceLogPath`, `auditLogPath`) are **never** rolled back, even if detected as modified
3. Records `EFFECT_ROLLBACK_COMPLETED` if all rollbacks succeed, or `ROLLBACK_CRITICAL_FAILURE` if any fail
4. The evidence ledger hash chain remains intact regardless of rollback outcome

## Security Improvements vs. v0.3.1

| Area | v0.3.1 | v0.4 |
|------|--------|------|
| Filesystem effect detection | None | SHA-256 diff before/after execution |
| Unauthorized write detection | None | SEC-004-UNAUTHORIZED-WRITE rule |
| Workspace boundary enforcement | PathGuard (pre-execution) | PathGuard + EffectFirewall (post-execution) |
| Rollback trigger | User-initiated or write failure | Automatic on any capability violation |
| Evidence chain | Execution events | + Effect events + impact scores |
| Audit granularity | Command level | Command + file-level mutation tracking |
| TOCTOU hardening | None | Path revalidated immediately before execution |
| Infrastructure integrity | None | Evidence/audit log excluded from rollback |

## Known Limitations

### Platform Limitations (by design)

1. **No kernel-level sandboxing**: The EffectObserver operates at the userspace filesystem level. It captures effects by taking before/after state snapshots, not by intercepting filesystem syscalls. A fast process that writes and immediately deletes a file within the execution window may not be detected.

2. **Network effects are heuristic only**: Network activity is inferred from command-line arguments (URLs, IP addresses, hostnames, ports). Actual TCP connections are not intercepted. This is documented as a heuristic, not a guarantee.

3. **Process tree lifecycle**: After `SecureProcessExecutor` kills a process tree, orphaned grandchildren may survive briefly. The `tree-kill` mechanism mitigates but cannot guarantee 100% elimination of all descendants in all OS configurations.

4. **Excluded directories**: Files written to `node_modules`, `.git`, or `dist` during execution are not tracked (by design — these directories are excluded for performance). A malicious script writing to `node_modules` would not trigger a `CAPABILITY_VIOLATION`.

5. **Race conditions**: Between `captureState()` and process execution, another concurrent process may modify files, producing false positives. In practice this is unlikely in a controlled CodeGuardian session.

### Architectural Limitations

6. **`node` interpreter is blocked**: The `CommandParser` correctly classifies `node` as a dangerous binary (arbitrary code execution). This means npm scripts that invoke `node` directly are blocked at the `NpmScriptAnalyzer` stage and never reach the EffectFirewall. The firewall is tested via direct pipeline integration testing.

7. **Rollback for DIR_DELETE**: Deleted directories are recreated as empty directories. Any files that were in the deleted directory are NOT restored (they would need prior snapshotting to restore).

- **Unit tests**:

  - `tests/unit/security/effectFirewall.test.ts` — violation detection by rule

  - `tests/integration/effectFirewallIntegration.test.ts` — end-to-end:
